# Pricing Management · 配送费定价管理平台

> 企业级**定价配置管理平台** —— 让"配送费怎么定"这件事 **配得清、管得住、发得准、查得对**。

---

## 一、项目简介

**Pricing Management（配送费定价管理平台）** 是面向物流 / 配送业务的定价**配置管理中台**，基于
**Spring Boot + MyBatis + Redis + Dubbo（ShardingSphere 预留）** 构建。

### 职责边界（重要）

本平台管理定价的"**定义与发布**"，**不负责在线计费执行**：

```
本平台职责：业务 → 定价场景 → 费用组(含多个费用) → 费用对应定价方案(绑定维度) → 方案 = 定价模板 + 定价因子
                                                    ├─ 展示模板（给平台展示用）
                                                    └─ 计算模板（计费时用，发布给下游计费引擎执行）
下游职责：  拉取已发布方案 → 在线计费 → 订单快照 → 交易链路（均不在本项目范围）
```

| 在本项目范围内 | 不在本项目范围 |
|--------------|--------------|
| 业务/场景/方案/维度/因子/模板的全生命周期管理 | 高并发计价服务及其流量 |
| 版本管理、审批流、发布与回滚 | 交易下单链路 |
| 发布数据一致性保障与核查（核心关注点） | 订单价格快照固化 |
| 向下游提供方案配置的分发接口（Dubbo/HTTP） | 计费引擎的执行性能与可用性 |

### 核心特性一览

| 特性 | 说明 |
|------|------|
| 分层模型 | 业务→场景→费用组→费用→方案→维度六级管理；组内费用具备名称/编码/顺序/必填四属性，同页面一并配置 |
| 双模板锁定 | 计算模板与展示模板**版本成对绑定**，发布时强校验，从机制上杜绝"展示与计算不一致" |
| 时间版本化 | 方案（pricing_scheme）以 **start/end 时间区间**表达版本：定时生效无需 job 触发、时点回放即审计、回滚复制新行 |
| 强一致事务 | **费用组粒度原子发布**：组内所有费用一并配置、一并提审、单本地事务整批落库，组内永不混新旧版本 |
| 内容哈希 | 发布时计算版本全量内容的 canonical 哈希（content_hash），下游拉取可校验、变更可感知 |
| 全程审计 | 谁改的、改了什么、谁批的、何时生效，操作级留痕可回放 |

## 二、系统定位：在大项目中处于什么位置

本平台处于配送业务架构的「**配置供给侧**」，是定价规则的**唯一编辑与发布入口（Source of Truth）**。

```
┌──────────────────────────────────────────────────────────────┐
│ 上游（使用者）                     本平台                      │
│  • 定价运营/商务   ──Web──▶  ★ Pricing Management（管理平台）  │
│  • 审批/风控人员   ──Web──▶                                  │
├──────────────────────────────────────────────────────────────┤
│ 下游（消费方，各自独立系统）        消费方式                     │
│  • 计费引擎系统     ◀── Dubbo/HTTP 拉取生效方案内容 ──────┐     │
│  • 费用展示服务     ◀── 拉取展示模板 + 因子明细 ─────────┤     │
│  • 数据分析/BI      ◀── 审计日志/版本历史同步 ───────────┘     │
│                     （下游按时间版本拉取，变更由其自行感知）    │
└──────────────────────────────────────────────────────────────┘
```

- **对运营**：定价配置的统一工作台（配置、试算校验、审批、发布、监控）。
- **对计费引擎等下游**：**只读配置源**——下游拉取"时间版本化的生效方案"，本平台不感知其流量压力。
- **对审计/合规**：定价数据的存证中心——任何价格配置的变更历史完整可回溯。

> 一句话定位：**定价数据的定义、管理、发布与一致性保障中心**；计费执行是别人的事，发布出去的数据对不对、一不一致，是本平台的事。

## 三、核心功能

### 3.1 功能模型层级（平台骨架）

```
业务（biz_line）                         例：即时配送、同城货运、生鲜到家
 └─ 定价场景（pricing_scene）             例：标准配送、恶劣天气、大促活动
     └─ 费用组（pricing_fee_group）       ★配置与发布单元：同一页面一并配置组内费用、整组原子发布
         └─ 费用（pricing_fee_item）      组内费用项：名称、编码、顺序、是否必填
             └─ 定价方案（pricing_scheme）  每个费用可 N 个方案实例并存（各绑不同维度）；每实例
                 │                          start/end 时间区间多版本；任意(费用×维度点×时点)唯一命中
                 ├─ 方案绑定维度                生效范围：城市/网格/商家分组/客户等级（同样时间版本化，决定实例归属）
                 └─ 定价方案（拆解）
                     ├─ 定价因子（factor）      原价、重量、体积、距离、天气、节假日、时间段、区域…（平台级字典）
                     └─ 定价模板（template）
                         ├─ 展示模板（DISPLAY） 给平台展示"费用如何构成"：文案 + 变量槽
                         └─ 计算模板（CALC）    计费时用的公式/查表结构
                             ★ 两模板输出字段绑定、版本锁定、发布时成对校验
```

### 3.2 功能模块清单

| 模块 | 能力 |
|------|------|
| **业务管理** | 业务线注册、状态、归属人 |
| **场景管理** | 场景定义、场景可用因子集约束（factor_scope） |
| **因子中心** | 平台级因子字典：值类型（数值/枚举/区间表/系数）、取值校验规则、分类 |
| **模板中心** | 计算模板（公式结构）与展示模板（文案+变量槽）的定义、版本化、成对绑定 |
| **费用组管理** | 组的定义与启停；**同一页面一并配置组内全部费用**，整组一并提审、原子发布 |
| **费用管理** | 组内费用项：名称、编码、顺序、是否必填（必填项发布前强制校验配齐） |
| **方案管理** | 方案（pricing_scheme）草稿、维度绑定、因子赋值、模板引用、复制/对比 diff、时间版本历史链 |
| **版本与发布** | 版本状态机（草稿→审批→发布）、start/end 区间版本化、定时发布（零 job 依赖）、回滚（复制历史行发新版）、灰度标记 |
| **审批流** | 提交/审批/驳回、双人复核、审批留痕 |
| **分发服务** | Dubbo/HTTP 只读接口：按业务/组拉取当前生效集、按费用+时点取方案全量内容 |
| **审计日志** | 全部写操作 before/after 留痕；时间版本行支持任意历史时点配置回放 |
| **并发控制** | 方案编辑锁（Redis）+ DB 乐观锁；发布并发由 DB 行锁、CAS 与终态复核保障 |

### 3.3 关键能力点

| 能力维度 | 技术方案 |
|---------|---------|
| **事务管理** | 发布动作 = 组粒度单本地事务（校验+闭旧版+转正版+审批终态+审计同事务）；不引入分布式事务框架 |
| **数据一致性** | 发布区间不重叠不变式（DB 行锁+CAS+终态复核）→ 版本行发布后不可变（仅允许闭合 end）→ content_hash 拉取可验证；时点回放查询支撑审计 |
| **分布式锁** | Redisson 仅用于方案编辑/修改/删除的排他锁；正确性以 DB 行锁/CAS/终态复核为准 |
| **RPC / 分发** | Dubbo 只读分发接口 + HTTP 开放接口（当前/历史生效集、按实例或费用范围+时点取方案内容），幂等、直查 DB |
| **服务治理** | Nacos 注册配置、超时/限流基础治理（管理平台低流量，治理以满足审计和隔离为准）|
| **设计模式** | 组合/解释器（计算模板公式树）、建造者（版本内容装配+哈希）、模板方法（状态流转/导入管道）、工厂（因子校验器）、外观（分发接口）、适配器（canonical 序列化/渲染） |
| **架构设计** | 模块化单体（Maven 多模块、单一部署、模块边界即服务边界），DDD 分层 |
| **分库分表** | 容量重算结论：时间版本模型总库量 <10GB，**无需分库分表**；审计日志按月分区，ShardingSphere 作为预案（见 data-model.md §8）|
| **缓存** | 不引入缓存层；管理端与分发读接口均直查 DB（读压 <100 QPS，索引覆盖） |

## 四、技术栈

| 分类 | 选型 | 用途 |
|------|------|------|
| 语言 / 框架 | Java 21、Spring Boot | 应用基座 |
| ORM | MyBatis | 数据访问 |
| 锁 | Redis + Redisson | 仅方案编辑/修改/删除的排他锁 |
| RPC / 治理 | Dubbo + Nacos | 对下游分发接口、注册与动态配置 |
| 消息 | RocketMQ（事件通知，可选） | 发布事件推送（下游亦可纯拉取） |
| 数据库 | MySQL 8.0 | 主存储（单库，审计日志按月分区） |
| 扩展预留 | ShardingSphere-JDBC | 数据量超预期时的分片预案 |
| 构建 | Maven 多模块 | 模块化单体 |

## 五、工程结构（模块化单体）

```
pricing-management (parent)
├── pm-common                公共模型 / 工具 / 异常 / 枚举
├── pm-api                   对下游分发契约（Dubbo 接口 + DTO）
├── pm-domain                领域模型：业务/场景/费用组/费用/方案/因子/模板 + 校验规则
├── pm-application           应用编排：用例、事务边界、组发布流程
├── pm-infrastructure        MyBatis / Redis锁 / MQ 实现
├── pm-admin                 Web 管理端接口（BFF，鉴权/审计切面）
├── pm-delivery              分发服务（Dubbo Provider + HTTP Open API）
└── pm-job                   定时任务：分区维护、历史归档、审计清理（无定时生效 job，时间自身即开关）
```

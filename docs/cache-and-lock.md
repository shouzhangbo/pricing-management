## 1. 设计前提：为什么可以完全没有缓存

| 问题 | 消解方式 |
|------|---------|
| 分发读接口不需要缓存吗？ | 读压 <100 QPS（D1/D7），生效集/内容查询全走 `idx_fee_status`/`idx_time` 点查与小范围扫，DB 直查 RT 可控；装配型 join 亦为小结果集 |
| 不加缓存少了什么？ | 少一层"缓存与 DB 视图差异"的心智负担——生效性由 `[start,end)` 区间定义，读到的永远是 DB 终态 |
| Redis 挂了的爆炸半径 | 仅编辑入口（§3）；发布、分发、查询、审计全部不受影响 |
| "正确性不依赖中间件"原则 | 由"Redis 不在正确性链路"升级为 **Redis 不在读链路**——只剩一个 UX 层的编辑互斥 |

## 2. 方案编辑锁（唯一锁）

### 2.1 锁登记表

| 项 | 设计 |
|----|------|
| 键 | `pm:lock:edit:{schemeId}`（方案实例粒度，覆盖草稿） |
| 保护操作 | 方案的**编辑、修改（保存草稿）、删除**三类写操作的入口 |
| 参数 | `tryLock(wait=0, lease=90s)` + 看门狗续期；拿不到立即失败，返回"XXX 正在编辑，请稍后再试" |
| 生命周期 | 编辑会话开始 → 提交/退出/超时释放；删除操作为短持有（拿锁→执行→释放） |
| value | `ownerToken`（UUID），解锁必须 Lua 校验 owner 再删（防误删他人锁） |

```lua
if redis.call('GET', KEYS[1]) == ARGV[1]
  then return redis.call('DEL', KEYS[1]) else return 0 end
```

规约（沿用 v2.0 的通用纪律）：

1. **wait=0 不排队**：编辑是人工操作，撞锁就提示重试，不排队放大等待；
2. **lease > 最坏操作耗时**：删除是秒级短操作；编辑会话靠看门狗续期；
3. **锁包住写事务**：拿锁在事务开启前、释放在事务提交后——防止"事务未提交锁先释放"的竞态窗口。

### 2.2 锁与正确性的关系（定位声明）

```
编辑锁: 体验与协作优化（防止两人互相覆盖编辑现场）。
        删除它数据仍一致——保存路径还有 row_version 乐观锁 CAS 兜底，
        并发后到的写入会收到 409 而不是静默覆盖。
```

### 2.3 已删除的锁及其职责去向（v2.0 → v3.0）

| 原锁 | 去向 | 理由 |
|------|------|------|
| L2 发布锁（组+费用级） | **删除**。发布并发由 DB 层独扛：`FOR UPDATE`（fee_id 升序 + next-key lock）+ 闭旧 CAS + S6 终态复核 | 发布是"校验在事务内、以 DB 终态为准"的设计，Redis 锁从来只是降冲突；写频极低（D7），冲突窗口可忽略，去掉后链路更短 |
| L3 任务锁（job 级） | **删除**。归档/分区/巡检 job 防重靠 XXL-JOB 调度中心单派发 + 路由策略，job 本身保持幂等（进度 CAS、按主键存在性判断） | 调度入口唯一，无需应用层再设锁 |

## 3. Redis 故障退化（fail-close，仅限编辑入口）

| 故障 | 行为 | 影响面 |
|------|------|--------|
| 加锁失败（连接异常/超时） | **编辑/修改/删除入口拒绝**，提示"系统繁忙，请稍后重试"；页面数据只读可看 | 仅配置人员短暂无法进入编辑 |
| 解锁失败 | 锁靠 lease/看门狗自然过期，最长 90s 后可重新进入 | 同上 |
| Redis 整体不可用 | 编辑入口整体暂停（fail-close）；**发布、分发、查询、审计、job 全部正常** | 运营低频操作，短时不可用可接受 |

- v2.0 的"全局 bypass 开关 + fail-open"机制随缓存一并删除；
- 备选方案（默认不做）：Redis 故障时放行编辑、完全靠 row_version 409 互斥——数据仍一致但协作体验退化为"互相弹 409"。是否启用留作运行期开关评审项。

## 4. 监控

| 指标 | 目标/阈值 | 用途 |
|------|----------|------|
| 编辑锁获取失败率 | 常态观测，突增=多人抢编同一方案 | 运营协作热点 |
| 编辑锁持有时长 P99 | < 编辑会话预期时长 | 发现看门狗/释放异常 |
| 409（row_version 冲突）返回数 | 应接近 0；>0 说明锁失效或绕过锁直调 API | 兜底防线是否被触发 |
| Redis 连接状态 / 编辑入口拒绝数 | 拒绝突增 → P2 告警 | 故障感知（仅此一个爆炸半径） |
